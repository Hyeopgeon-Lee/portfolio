작품 설명
찍고먹어요는 냉장고 사진 한 장으로 식재료를 자동 인식하고 요리를 추천해주는 AI 기반 냉장고 식료품 분석 및 요리 추천 서비스입니다.

사용자는 냉장고 사진을 업로드하면 AI가 식재료를 자동으로 인식하고, 보유 재료 기반의 레시피를 추천합니다. 사용자는 인식된 식재료를 직접 교정할 수 있으며, 교정된 결과를 기반으로 최적의 레시피를 제안합니다.

프론트엔드에서는 AVIF 등 비표준 이미지 포맷을 Canvas API를 활용해 JPEG로 변환한 뒤 업로드하는 방식을 적용하여 다양한 기기 환경을 지원합니다. 이미지 업로드는 Spring Boot에서 AWS S3 Presigned URL을 발급받아 브라우저가 S3에 직접 PUT 요청하는 방식으로 구현하여 서버 부하를 최소화했습니다.

AI 서비스는 FastAPI와 Python 기반으로 구성되었으며, Google Gemini API를 활용해 냉장고 이미지 내 식재료 객체 인식 및 분석, 선택한 레시피의 YouTube 영상 직접 분석을 통한 조리 단계 타임라인 생성을 수행합니다. Gemini API 호출 시 503·429 응답에 대해 지수 백오프(Exponential Backoff) 기반 재시도 로직을 적용하여 서비스 안정성을 확보했습니다. 또한 Pinecone 벡터 DB와 연동하여 식품 영양 정보 유사도 검색을 수행합니다.

레시피 선택 후 사용자는 조리 타임라인 페이지에서 YouTube 영상과 AI가 생성한 단계별 조리 가이드를 동시에 확인할 수 있으며, 각 단계 클릭 시 해당 영상 구간으로 자동 이동합니다. 부족한 재료는 Naver 쇼핑 API를 통해 검색하고 장바구니에 담을 수 있습니다.

인증은 JWT 기반으로 구현하였으며, Access Token과 Refresh Token을 모두 HttpOnly + Secure + SameSite=Lax 쿠키로 발급하여 XSS 공격에 대한 보안성을 확보했습니다. Access Token은 Redis 블랙리스트(BL:AT:{jti}) 기반으로 로그아웃 후 재사용을 차단하고, Refresh Token은 Redis 화이트리스트(RT:{userId})에 저장하여 RTR(Refresh Token Rotation) 방식으로 재사용 공격을 방지했습니다. 비밀번호는 SHA-256으로 암호화하여 저장합니다.

Spring Security 설정에서 STATELESS + NullSecurityContextRepository를 적용하여 서버 세션을 완전히 제거했으며, 커스텀 CookieOrHeaderBearerTokenResolver로 쿠키에서 JWT를 추출하고, JwtBlacklistFilter로 블랙리스트 검증을 수행합니다.

배포 환경은 AWS EC2(t3.micro)에 Spring Boot와 FastAPI(Docker 컨테이너)를 함께 운영하며, Nginx를 리버스 프록시로 사용하고 Let's Encrypt 기반 HTTPS를 적용하여 실제 웹 서비스 형태로 운영 중입니다.
